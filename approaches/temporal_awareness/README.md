# 思路二：时序事件边界采样 (Temporal Event Boundary Sampling)

> **核心思想**：机器人操作由离散动作事件串联而成（接近→抓取→转移→放置）。事件边界处（动作突变）的信息价值高于稳定段。模拟海马体的事件分割理论——大脑对行为转换时刻分配更多注意力。

---

## 动机

冗余分布思路（v1.1）只利用了**空间特征**的静态分布，完全忽略了数据的**时序结构**。在机器人操作中：
- **稳定段**：机械臂缓慢移动，连续几十帧动作和视觉几乎不变 → 时序冗余
- **事件边界**：抓取、放置、松开等动作突变 → 关键教学信息

本思路独立验证：仅用时序信息（动作变化率）选择核心集，效果究竟如何？

---

## 算法

### Step 1 — 动作变化率计算

```python
δ(t) = ||A[t] - A[t-1]||₂      # 跨关节 L2 范数
```

跨 episode 边界处重置为 0，避免不同 episode 之间的虚假变化率。

### Step 2 — 事件边界检测

在每个 episode 内，用百分位数阈值找局部峰值：
- `threshold = percentile(δ, 85)`
- 局部峰值：比左右邻居都大，且超过阈值
- `min_peak_distance=5`：避免事件边界过密

### Step 3 — 分层采样

```
Layer 1: 事件边界帧保底入选
Layer 2: 每个 episode 至少保底 1 帧（变化率最高的）
Layer 3: 若不足 target_size，全局按变化率补齐
Layer 4: 若超过 target_size，保留变化率最高的帧
```

## 分析

### 为什么 standalone 时序思路效果差？

#### 直接原因：空间覆盖崩溃

1. **空间盲区**：只选动作变化大的帧，可能集中在少数几个 episode 的密集动作区域，忽略了空间分布的均衡性
2. **噪声敏感**：操作中的微小抖动会被检测为"事件边界"，但这些抖动帧的教学价值有限
3. **缺失稳定段信息**：某些任务的"稳定执行"阶段（如匀速转移）本身也包含关键信息，被完全丢弃

#### 根本原因：单任务数据集的时空耦合

本数据集（ALOHA transfer cube）的结构性缺陷加剧了上述问题：

- **50 个 episode 遵循同一脚本**：接近 → 抓取 → 转移 → 放置
- **事件边界在时间上高度对齐**：每个 episode 的"抓取"发生在相似的时间点
- **事件边界在视觉空间上高度重叠**：抓取时的视觉状态在不同 episode 之间几乎相同

> 时序方法选出的 **539 个事件边界帧**，本质上是 **50 次重复的同一场景**。

**时序方法的底层假设在这个数据集上被破坏了**：

| 时序方法的假设 | 在本数据集上的现实 |
|--------------|----------------|
| "事件边界 = 高信息价值" | 事件边界高度重复，信息冗余 |
| "不同时刻的边界覆盖不同状态" | 所有 episode 的边界在视觉空间中重叠 |
| "时序分散 = 信息分散" | 时序上分散，但空间上扎堆 |

这导致时序核心集虽然在时序维度上"分散"，但在视觉特征空间中严重**扎堆**，没有实现空间覆盖的均衡——而空间覆盖恰恰是决定模型泛化性能的关键因素。

#### 反直觉的发现

**时序方法在本数据集上的失败，恰恰证明它可能在更复杂的数据集上有效**：

- **多任务数据**（如 Open X-Embodiment，几十种机器人、几百个任务）：不同任务的事件边界发生在完全不同的视觉空间，时序方法会自动覆盖多样化的空间区域
- **长程复杂任务**（如半小时的整理房间）：事件边界本身就是稀疏且多样的

> 失败不是方法的错，是数据集太简单。

### 价值与后续方向

本实验的核心价值是**否定性验证**：
> 纯粹的时序信息**不能替代**空间分布信息，但可以作为**补充维度**。

后续融合实验（空间多样性 × 时序变化率）有潜力超过单一思路——空间多样性保证"不扎堆"，时序变化率保证"不偏废稳定段"。
